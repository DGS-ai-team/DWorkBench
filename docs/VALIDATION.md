## 本机 WSL 实测

同日通过 tests/wsl-integration.mjs 完成。Windows 上的 LogDesk 后端通过真实网络 SSH/SFTP 连接本机 WSL2 Ubuntu 26.04；服务端实现为 OpenSSH 10.2p1。测试通过独立应用进程和 SQLite 数据库运行，未修改 http://127.0.0.1:5080 的开发预览数据。

- 在临时目录创建 253 个匹配日志文件，另加不匹配文件和符号链接；SFTP 结果正确排除后二者，分页为 200 + 53 项，文件 ID 无重复。
- 将 SSH.NET 探测指纹与 ssh-keygen 输出逐字核对，确认固定指纹后密码认证成功。
- 含空格、单引号、中文和 UTF-8 符号的日志文件，下载原始字节与 Linux 文件一致。
- 初始为空的文件能显示连接状态，并收到首次追加内容。
- Ubuntu 默认 tail 为 uutils coreutils 0.8.0；系统另有 /usr/bin/gnutail（GNU coreutils 9.7）。两者均通过初始读取、持续追加、截断、rename/create 轮转和删除后重建验证。GNU 验证仅调整临时 sshd 的 PATH，没有替换系统 tail。
- 在现有 /var/log/dpkg.log 上只读验证：扫描成功，下载 362,531 字节；下载结果与 Linux 原文件 SHA-256 相同；流式输出末尾 200 行与直接执行 tail 的结果相同。没有修改或轮转系统日志。
- Chromium 通过搜索分别勾选两个文件，跨筛选保留选择，双窗格显示真实内容并接收追加；独立停止后远端 tail 进程数由 2 降至 1，关闭页面后降至 0，无 pageerror。
- 单流取消和窗口关闭后实际检查远端 tail 进程，扫描、下载和流操作的审计记录存在，记录中没有 SSH 密码。
- 所有临时 Linux 账号、独立 sshd 和临时日志目录在 finally 中清理；原有 SSH 配置和端口 22 未改动。WSL 保持启动状态。

复现前需要已完成前后端构建和 Chromium 安装，WSL 发行版可用并允许通过 wsl.exe -u root 启动命令，且已安装 OpenSSH server、Python 3、默认 tail 和 /usr/bin/gnutail。本次未额外安装 Linux 软件包。

```powershell

```

默认发行版 Ubuntu，可通过 WSL_DISTRO 环境变量指定；其他发行版需确认 GNU tail 的位置。SKIP_BROWSER=1 可跳过浏览器部分。结果和服务日志保存在已被 Git 忽略的 .local/wsl-integration-*/；本次最终报告为 .local/wsl-integration-KFe8Fq/result.json，双窗格截图为 .local/wsl-live-workspace.png。

此验证证明 Windows 应用可通过真实 SSH/SFTP 读取 Linux 日志，不能视为多台真实服务器、Windows Server 服务安装或大规模吞吐量验收。

## 2026-11-02 第一阶段：回归与稳定性收尾（0.8.1）

本阶段完成本机 MVP 核心流程和故障隔离回归。使用独立 SQLite 数据目录、独立 PostgreSQL 数据库、回环 SSH 模拟服务及 WSL 临时账户；未修改开发预览的主机、来源、日志组或权限，也未改动 NAS 日志。

### 修复

1. **实时滚动使菜单闪退**：菜单原来监听所有捕获阶段的滚动事件，日志正文自动跟随也会关闭菜单。现在仅在触发按钮的祖先容器滚动时关闭，窗口 resize 单独处理。四路各约 1,000 行/秒时，窗格及关注菜单保持可操作。
2. **重连后缺少中断告知**：停止后继续、SSH 错误后重连统一走恢复流程，在收到服务端就绪帧后显示可关闭的持续提示：读取的是最近快照，中断期间内容可能未显示，统计重新开始。避免把重连呈现成无损续传。
