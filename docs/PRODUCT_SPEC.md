# DWorkBench 产品设计与 MVP 需求

- 文档版本：0.8
- 日期：2026-11-02
- 产品形态：团队共享的 B/S Web 应用（Windows 浏览器优先）
- 产品名：DWorkBench
- 阶段：MVP 已实现；待目标 Windows VM 与真实管理网络验收

## 1. 产品目标

DWorkBench 帮助团队通过浏览器管理多台远程 Linux 主机。MVP 聚焦共享日志源和日志组：成员可以跨服务器筛选日志、只打开选中的文件进行多窗格实时查看、下载文件，并按角色和资源权限协作。服务端统一发起 SSH/SFTP 连接，记录谁在何时对哪些资源执行了什么操作。

核心结果：配置一次后，日常查看日志不需要反复输入 SSH 命令，也不需要为每个日志单独打开终端窗口。

## 2. 目标用户与典型场景

### 目标用户

- 需要排查 Linux 服务问题的开发人员。
- 需要同时观察多个服务或环境日志的运维、测试人员。
- 需要共享主机与日志配置、并按职责查看日志的开发、测试和运维团队。
- 负责用户、权限、主机连接和日志来源配置的管理员。

### 典型场景

1. 管理员创建服务器连接，验证地址、端口和账户，并确认服务器指纹；授权成员可访问相应主机或日志组。
2. 用户为该服务器添加日志源：目录 `/var/log/myapp`、文件模式 `app-*.log`。
3. 用户把不同服务器上的多个日志源收进“生产环境”日志组。
4. 团队成员登录后打开共享日志组，按需扫描一个或多个服务器/日志源；从合并清单中筛选并勾选有权限访问的日志，再显式打开到工作区窗格。
5. 用户在同页并排查看 API、worker 等多个日志流，暂停或停止某个窗格，并下载需要留存的文件。
6. 管理员查看审计记录，追踪配置变更、权限变更、日志访问和下载的操作者、目标及结果。

## 3. 信息架构与页面构想

主窗口采用日志画布优先的单页工作台。日志清单按需以覆盖式抽屉打开；用户选择的少量文件进入可折叠的关注列表，主区域展开一到两个阅读窗格。日志组是跨服务器的集合；清单扫描、选择日志和打开实时流是分开的动作，避免切换日志组时隐式打开大量连接：

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ DWorkBench  [生产环境 ▾] [3/3 主机在线] [日志清单] [布局 ▾] [专注模式] [设置] │
├─────────────────────────────────────────────────────────────────────────────┤
│ ┌──────────────────────────────────┬──────────────────────────────────────┐ │
│ │ api.log · 10.0.0.8/API · LIVE    │ worker.log · 10.0.0.12 · LIVE       │ │
│ │                                  │                                      │ │
│ │      实时日志内容（主工作区）    │       实时日志内容                   │ │
│ │                                  │                                      │ │
│ └──────────────────────────────────┴──────────────────────────────────────┘ │
│                         （日志清单抽屉默认关闭）                            │
└─────────────────────────────────────────────────────────────────────────────┘
```

- 顶栏：固定高度的紧凑工具栏，只显示当前日志组、主机连接摘要、“日志清单”、布局和专注模式。主机/来源细节放入清单抽屉。
- 主画布：一个或两个阅读窗格，支持左右/上下及拖动分隔线。关注列表宽 280px，可折叠；窄屏覆盖展开。关注文件最多四个，后台文件不渲染日志正文。
- 清单抽屉：从顶栏按需打开，以覆盖层出现在工作区上方，不永久缩小窗格尺寸。抽屉内提供日志源搜索及主机/来源筛选；一个日志组可以混合多台主机上的来源。来源名前显示主机别名和连接状态，可勾选来源作为扫描范围。
- 清单区：每行包含复选框、文件名、服务器、日志源、修改时间和大小；支持文件名搜索、主机/来源筛选、时间范围、排序和分页。扫描中的来源逐个返回结果，不等全组完成才显示。
- 选择与打开：勾选不建立流。“仅加入关注”启动后台跟踪，“加入并阅读”还展开至多两个主窗格。已有同主机/路径/编码的文件复用本地会话并定位；新增关注超过四个时提示减少选择。
- 日志内容：默认使用高密度等宽字体并关闭自动换行，以显示更多行；长行通过水平滚动查看，用户可打开自动换行。搜索和控制收在紧凑窗格标题栏，专注模式隐藏顶栏和非必要 chrome。
- 单个日志窗格：文件名与服务器、连接状态、冻结显示/恢复、停止/继续订阅、清空本地显示、自动滚动、模式筛选和下载入口。筛选与格式细节以覆盖层按需展开，保留日志展示面积。
- 小窗口下抽屉改为全屏清单选择页；日志视图优先保留可读宽度；窄屏响应方式在 UI 原型阶段验证。

此处是信息布局，不是最终视觉稿；颜色、密度、主题、图标和细节交互待视觉方向确定后再做。

## 4. 核心对象

| 对象 | 含义 | 示例 |
|---|---|---|
| 服务器连接 | 主机、端口、用户名、认证引用、已确认的主机指纹 | `prod-01 / 10.0.0.8:22 / deploy` |
| 日志源 | 一个服务器上的目录、文件名模式及文本编码 | `/var/log/api` + `api-*.log` |
| 日志组 | 任意多台服务器上的多个日志源的命名集合，用于跨主机汇总和筛选 | “生产环境”包含 10.0.0.8 上的 API、10.0.0.12 上的 worker |
| 日志文件 | 由日志源扫描发现的远程文件元信息 | 路径、文件名、大小、修改时间 |
| 关注会话 / 阅读窗格 | 关注会话持有订阅和有限缓存；窗格展示其中一个会话 | `api-2026-10-30.log` |

日志组只定义来源集合，不要求来源属于同一服务器。每个日志源独立引用一个服务器连接，因此同一组可以跨环境、集群或云主机。

日志模式 MVP 使用文件名级 glob：`*` 匹配任意长度字符，`?` 匹配单个字符；不将输入解释为正则表达式，也不允许模式跨目录。每个日志源可选文本编码，默认 UTF-8。

## 5. MVP 功能范围

### 必须包含

1. **连接配置**：主机/IP、SSH 端口、用户名、密码；连接测试；新主机首次连接时核对并确认 SSH 主机指纹。
2. **日志源与日志组**：为连接配置一个或多个目录/文件名模式；把日志源加入具名日志组；编辑、删除和复制配置。
3. **跨服务器日志清单**：一个日志组可引用多台服务器上的任意日志源；按服务器/来源分组展示；用户可选择扫描范围；支持文件名、主机、来源和时间筛选，以及按需刷新。
4. **大清单浏览**：结果渐进呈现；虚拟化长列表；按游标读取共享元数据索引；显示扫描进度、来源连接状态和部分失败；缓存可立即显示并后台刷新。
5. **选择性关注**：清单以覆盖式抽屉按需出现；用户确认加入关注后才建立流。总计最多四个关注会话，其中一到两个展开阅读，其余后台跟踪；不自动跟踪整个日志组。
6. **实时日志**：默认打开最新约 200 行后持续跟随；同文件共享上游读取，各查看者独立授权和退出。支持自动滚动、冻结显示、文本/通配符/正则包含与排除、大小写、等级及上下文筛选；只检索当前保留窗口。
7. **下载**：通过 SFTP 将选中文件保存到本地；显示进度；同名覆盖前确认。下载内容按字节保存，不做文本转码。
8. **团队账号与权限**：支持管理员创建/停用本地账号和分配角色；按日志组及主机范围授权查看、扫描、下载和配置操作；后端逐请求执行授权检查。
9. **操作审计**：记录登录结果、权限与配置变更、扫描、打开/关闭日志流和下载的操作者、时间、目标、动作及结果；审计页按时间、人员、资源和结果筛选。审计不保存日志正文或凭据。
10. **基础可用性**：连接、权限、文件不存在、指纹变化、网络中断时给出可理解的状态和下一步操作；支持清空单个窗格的本地显示缓冲。

### 暂不纳入首版

- SSO/OIDC 接入；首版使用 DWorkBench 本地账号。企业登录作为后续身份提供方接入。
- 私钥/证书认证、跳板机和 SSH 代理配置。
- 编辑、上传或删除远程日志；任意命令终端；远程日志搜索/下载整目录。
- 多租户、跨团队隔离、复杂审批流、外部 SIEM 集成和遥测。
- Rundeck/Ansible 集成；Ansible 是后续批量运维能力的候选执行器。
- 告警、完整结构化字段提取、多行事件合并、远端全文检索和跨窗格查询；当前仅支持本地模式筛选和等级提取。
- 保存和分享复杂窗格布局；首版只保存日志组/日志源，当前打开的窗格由本次工作会话管理。

## 6. 主要交互规则

- 对跨主机日志组，服务端逐个来源校验成员是否同时拥有日志组权限和对应主机权限；清单只展示有权访问的来源，扫描、流式查看与下载请求都重新校验。
- 未保存或未验证的连接也可以编辑，但不能开始列目录或流式读取。
- 第一次遇到主机指纹时显示指纹及 SHA-256 摘要，用户确认后才保存；指纹变化时阻止连接并要求重新核验。
- 切换日志组更新来源范围，不自动扫描所有主机，也不替换正在查看的窗格；已有流会继续并显示其主机和来源。
- 扫描来源和打开流是不同操作。扫描只读取远端目录元数据，不启动 `tail`；勾选具体文件并确认加入关注后才启动流。
- 加入关注受四个文件总额度限制；加入并阅读最多展开两个。卡片点击切换当前活动窗格，原文件继续后台关注；固定窗格不被切换替换。
- 停止只取消该窗格订阅，不中断其他查看者；最后一个订阅退出后短暂宽限再释放远端读取。继续读取最近快照，可能跳过停止期间内容并明确提示。
- 冻结显示仍继续接收至有界实时缓冲；冻结期间可以筛选快照，恢复时回到当前保留内容。前端显示最多 10,000 行或 200 万字符，超长行截断并提示；不承诺保存完整历史。
- 等级着色采用保守自动识别，可选纯文本、JSON 等级字段或自定义等级提取正则；未知格式保持中性。正文关键词不作为整行等级的通用依据。
- 筛选按行匹配，排除优先；无效模式保留上一有效规则并提示。每窗格偏好随账号的最近工作台保存，当前不共享格式模板。
- “清空”只清理本地可视缓冲，不影响远程文件。
- 流断开时保留已有内容，展示断开原因，并提供手动重连；自动重试采用有限退避且可取消。
- 窗格显示缓冲有上限，避免长期跟随日志导致客户端内存持续增加；达到上限时丢弃最旧显示行并提示。
- 本地登录失败和被拒绝的资源访问也进入审计；授权以服务端策略为准，不能通过直接请求 API 绕过。
- 审计事件包含资源和动作元数据，不记录密码、令牌、私钥或日志正文。

## 7. 关键验收结果

- 用户能配置多台主机、多个目录和模式，并通过一个日志组筛选对应日志清单。
- 同一日志组可包含至少两台不同服务器的来源；清单能标明每条日志来自哪个主机和来源。
- 面对大量匹配文件时，界面能渐进显示和筛选结果；扫描清单不会自动启动日志流。
- 用户能从一批匹配日志中只勾选部分打开，新增关注超过可用额度时得到清晰提示。
- 清单关闭时，日志窗格占据工作区主体；清单抽屉打开/关闭不改变活动窗格尺寸或中断流。
- 用户能在同一主窗口打开至少两个日志流，独立停止其中一个，另一个仍正常显示。
- 文件轮转后，仍查看同一路径的新文件内容；连接中断后窗格状态清晰且可恢复。
- 下载后的文件可由本地工具读取，字节内容与传输时的远端文件一致。
- 多个团队账号能看到同一份已共享的日志组配置；未获授权的账号不能通过 API 读取清单、启动日志流或下载文件。
- 对包含多台主机的日志组，成员只看到自己同时获准访问的日志组与主机来源；直接调用 API 也不能越权读取其他来源。
- 可从审计记录确认谁在何时查看/下载了哪个主机上的日志，以及谁修改了主机、来源、日志组或权限。
- 主机凭据只保存在服务端的受保护存储中；数据库直接泄露不足以还原凭据；未知或变化的主机指纹不会被静默接受。

## 8. 已定决策与待确认项

- 首版是单一团队共享的 B/S 应用，Windows 用户通过浏览器访问；不做多租户。
- 首版使用 DWorkBench 本地账号与简单角色/资源级授权；暂不接入已有 SSO，后续通过 OIDC 接入。
- MVP 不部署 Rundeck 或 Ansible。后续批量主机操作优先评估 Ansible；当前 SSH.NET 远程访问接口需与未来作业执行器解耦。
- 首个部署节点为管理网络内现有的 Windows Server 2022 VM，用户提供的配置为 CPU 主频 2.6 GHz、64 GB 内存、D 盘约 1 TB 可用空间，且已确认可通过 SSH 访问全部目标主机。Web 后端以 Windows 服务运行，同机运行 PostgreSQL；团队浏览器通过 HTTPS 访问 VM，由服务端统一连接 Linux。MVP 不依赖 WSL，应用与业务数据优先放在 D 盘。
- 当前开发保持核心服务可移植到 Linux，隔离服务托管、文件路径和证书加载等平台差异。MVP 正式部署验收以 Windows Server 2022 为准；Linux 安装、完整集成验证和运维支持在迁移阶段补齐。浏览器 UI 与服务器操作系统解耦。
- 远端默认是启用 SSH/SFTP 且提供 GNU `tail` 的常见 Linux 发行版；精简 BusyBox 环境、受限 shell 和强制 MFA 是否纳入后续适配需要真实服务器验证。
- 首版建议每位用户最多 4 条活动流；服务端另设每主机和全局并发配额，避免多用户叠加占满 SSH 连接。
- 首版连接配置继续支持用户提供的 SSH 密码；凭据由服务端加密保管。私钥/短期证书认证作为后续优先候选。
- 文本实时显示按日志源配置的编码解码；首版默认 UTF-8。下载始终保留原始字节。
- 视觉设计阶段需要确定浅/深色主题、字体和密度，并用真实长日志内容验证窗格尺寸、搜索体验与高 DPI 表现。
- 尚需确认 vCPU 数量、存储性能、团队浏览器到 VM 的 HTTPS 可达性、部署规模（成员、主机、来源和目录文件数），以及用户账号开通/找回流程。不能仅凭 CPU 主频推断最大并发量。

## 9. 迭代建议

1. **团队基础**：Web 登录、本地用户管理、资源级授权、共享主机/日志源/日志组、审计事件。
2. **日志能力**：指纹确认、SFTP 清单、渐进扫描、下载、单窗格实时跟随与轮转恢复。
3. **工作台体验**：1/2/4 分窗、独立控制、过滤/查找、高密度显示和部署运维。
4. **扩展能力**：OIDC/SSO、私钥/证书与跳板机、保存布局、SFTP 轮询流、Ansible 批量任务。


## 0.7 工作台交互修订

- 关注列表属于个人当前会话；日志组属于团队共享配置。切换日志组不清空已关注文件。
- 后台卡片提供主机/文件、连接状态、最后收到数据的相对时间、近 60 秒接收量、独立关注规则命中量与最近原文摘录。用户顺序固定，不自动抢焦点或重排。
- 关注规则支持文本、通配符及 RE2，独立于阅读筛选。修改规则重新开始统计；显式共享回放不计接收量，首次 tail 返回的尾部数据计入接收，指标不称为“新增日志”。规则命中按行计数，不代表故障数。
- “收起”保留订阅与缓存；“停止”取消订阅并保留已有画面；继续时清空旧接收窗口、读取最近快照，明确停止期间可能缺失。移出列表释放该会话。
- 冻结显示不会停止接收；冻结时禁用跟随按钮并隐藏“回到最新”，统一使用“恢复实时显示”。切换窗格保留冻结、格式、阅读筛选与缓存内阅读位置。

## 0.9 最近工作台

- 每个账号自动保存一份最近工作台，包含当前组、关注项、双窗布局、固定状态、侧栏、筛选、日志格式、换行和关注规则。
- 重新进入时先恢复布局，点击整体或单项“恢复接收”后连接；只展开阅读窗格不会隐式恢复停止的订阅。
- 失效项保留位置并说明原因，允许重新检查或移除。其他有效日志可以独立恢复。
- 保存失败和多页面冲突按需提示；没有持续占用正文空间的保存状态栏。
- 保存配置不代表保存日志正文、接收计数或离线历史；恢复读取最近快照，继续保留原有配额和有界缓存。
- 命中可标为已查看；“定位”显式清除阅读筛选并解除冻结，定位最近命中并高亮。目标已淘汰时提示下载原文件。
- 清单标记已关注/阅读中，展示缓存更新时间及来源搜索，区分刷新来源和选择跟踪文件。
- 配置流程增加下一步操作：保存主机后测试身份，连接成功后添加日志源；来源保存前检查目录匹配；来源可创建预选日志组；日志组直达清单或团队权限。
- 管理员权限为只读全选；其他成员可预览组和主机交集产生的实际读取/下载范围。审计首次读取展示加载态。
- 本版尚未增加保存工作区组合、团队共享格式默认值、更多后台订阅或服务端摘要通道。

## 0.8 界面精简

- 删除全局页脚、英文装饰标题、常驻功能介绍、重复关注数量与窗格底部常驻统计。缓存淘汰和截断发生时仍显示提示。
- 关注列表最多四项，移除搜索和仅待看筛选。阅读中的卡片默认只展示身份与状态，有待看命中时保留摘要；后台卡片继续展示最近原文或命中。最近接收时间始终可见。
- 卡片仅在未展开且已有阅读窗格时提供“并排”。点击命中摘要或“条待看”徽标定位原文；标为已查看、规则、停止接收、移除与接收统计放入更多菜单。
- 窗格标题常驻冻结、原文件下载、更多、收起，双窗时显示固定入口。换行、复制可见内容、清空显示和停止/继续接收放入更多菜单。仅在脱离跟随时显示“回到最新日志”。
- 阅读筛选保留模式、清除和结果数，大小写设置移入高级面板。提示明确仅筛选已接收且保留的内容；通配符/正则说明按所选模式显示，缓存说明按需展开。纯文本模式隐藏等级范围。
- 文件清单保留文件搜索、主机/来源/时间筛选、多选、修改时间、大小、下载和两种加入方式。刷新来源默认全选，范围面板按需展开；扫描失败会展开详细原因；来源超过八项才显示来源搜索。
- 配置引导在尚无可用日志组时对管理员展开，完成后改为“配置指引”入口；保存后的下一步衔接保留。配置行的创建关联资源、复制、删除移入更多菜单，原有授权不变。
- 本轮不调整共享读取、Worker 调度、缓存上限、订阅配额和权限模型；不包含管理导航重组。
